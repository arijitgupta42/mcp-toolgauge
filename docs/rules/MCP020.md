# MCP020 -- parameter missing description

**Severity:** warning &nbsp;&nbsp; **Rule name:** `parameter-missing-description`

A parameter has no description.

## Why it matters

Selecting the right tool is only half of a successful call. The model then has to
invent arguments, and an undocumented parameter is a value it has to guess from the
name alone. `user` -- is that an ID, an email, a display name?

Watch out for `title`. Servers built on Pydantic emit an auto-generated `title` for
every field, so `query` arrives with `title: "Query"` attached. In a JSON dump that
looks like documentation. It is the parameter name with a capital letter, and this
rule does not count it.

## Triggers when

A parameter's subschema has no `description`, at the top level or inside an `anyOf`
branch. An auto-generated `title` never satisfies it.

## Before

```python
@mcp.tool()
def create_ticket(subject: str, body: str, user: str) -> Ticket:
    """Open a support ticket."""
```

## After

```python
@mcp.tool()
def create_support_ticket(
    subject: Annotated[str, Field(description=(
        "One-line summary of the problem, as it appears in the queue."))],
    body: Annotated[str, Field(description=(
        "Full description, including any error messages the user saw."))],
    requester_id: Annotated[str, Field(description=(
        "User ID of the person reporting the problem, e.g. 'usr_1a2b'."))],
) -> Ticket:
    """Open a support ticket on behalf of a user."""
```
