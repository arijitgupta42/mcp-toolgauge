# MCP013 -- overlapping descriptions

**Severity:** error &nbsp;&nbsp; **Rule name:** `overlapping-descriptions`

Two tools' descriptions are near-identical.

## Why it matters

This is the finding that explains most mysterious tool-selection failures. Two tools
whose descriptions are near-copies are a coin flip at selection time, and it is a
coin flip nobody observes: the call succeeds, returns plausible data, and the wrong
tool quietly captures a share of the traffic meant for its sibling.

Note what this rule does *not* say. Overlap between siblings is normal -- two search
tools over the same directory should have similar descriptions. This rule fires only
at near-copy-paste levels. Moderate overlap with no guidance is MCP014.

## Triggers when

Two tools' descriptions share at least 70% of their meaningful words, measured as
Jaccard similarity over content words with stopwords removed and plurals folded.
Pairs where either description has fewer than six meaningful words are skipped: two
stubs collide trivially, and MCP011 already reports them.

The threshold was set against real servers. A carelessly-written pair of sibling
search tools scores 0.78; a carefully-written pair covering the same domain scores
0.57.

## Before

```python
@mcp.tool()
def search_users(query: str) -> list[User]:
    """Searches the database and returns matching records for the given query."""

@mcp.tool()
def search_orgs(query: str) -> list[Org]:
    """Searches the database and returns matching records for the query given."""
```

## After

```python
@mcp.tool()
def search_users(query: str) -> list[User]:
    """Find individual people by name, email, or employee ID. Use this when the
    user wants a *person*; for a company or team, use `search_organizations`."""

@mcp.tool()
def search_organizations(query: str) -> list[Org]:
    """Find companies, teams, and departments by name or email domain. Use this
    when the user wants a *group*; for one person, use `search_users`."""
```
