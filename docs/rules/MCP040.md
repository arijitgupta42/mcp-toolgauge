# MCP040 -- destructive tool without destructiveHint

**Severity:** error &nbsp;&nbsp; **Rule name:** `destructive-tool-without-hint`

A tool that looks destructive declares no destructiveHint.

## Why it matters

The one rule here that is about safety rather than selection. A client that cannot
tell a delete from a read has two options and both are bad: confirm everything, which
trains users to click through prompts without reading them, or confirm nothing.

Annotations are how you get the good outcome instead -- a prompt on the calls that
deserve one, and silence on the calls that do not.

## Triggers when

`destructiveHint` is unset (the server said nothing, as distinct from saying `false`)
and the tool looks destructive: a name containing `delete`, `remove`, `purge`,
`wipe`, `revoke`, `truncate` and similar, or a description containing "permanently",
"cannot be undone", "no undo", or "irreversible".

## Before

```python
@mcp.tool()
def delete_all_tickets(org: str, confirm: bool = False) -> dict:
    """Deletes every ticket belonging to an org. There is no undo."""
```

## After

```python
DESTRUCTIVE = ToolAnnotations(
    readOnlyHint=False, destructiveHint=True, idempotentHint=True
)

@mcp.tool(annotations=DESTRUCTIVE)
def delete_all_tickets(organization_id: str) -> DeletionResult:
    """Permanently delete every ticket belonging to an organization.

    This cannot be undone. To take tickets out of the active queue reversibly,
    use `archive_ticket` instead."""
```
