# MCP014 -- no disambiguation guidance

**Severity:** warning &nbsp;&nbsp; **Rule name:** `no-disambiguation-guidance`

A tool overlaps with a sibling and never says which to prefer.

## Why it matters

Overlap between sibling tools is normal and usually unavoidable. What separates a
server whose tools get picked correctly from one whose tools do not is whether the
descriptions say *how to choose*.

One sentence is enough: "Use this when X. If you need Y, use `other_tool` instead."
That single line does more for selection accuracy than any amount of rewriting the
rest of the description, because it turns an ambiguous match into an explicit rule
the model can follow.

## Triggers when

A tool's description shares at least 35% of its meaningful words with another
tool's, and contains neither a mention of that sibling by name nor any steering
language ("instead", "rather than", "use this when", "unlike", "only when").

Deliberately generous: the aim is to reward an author who wrote any guidance at all,
not to insist on a house phrasing. Reported once per tool, not once per pair.

## Before

```python
@mcp.tool()
def get_user_profile(user_id: str) -> UserProfile:
    """Retrieve the full profile for one person, with contact details."""
```

## After

```python
@mcp.tool()
def get_user_profile(user_id: str) -> UserProfile:
    """Retrieve the full profile for one person, with contact details.

    Use this only when you already have a user ID. If you have a name or an
    email and need to resolve it first, call `search_users`."""
```
