# MCP051 -- server tool budget exceeded

**Severity:** warning &nbsp;&nbsp; **Rule name:** `server-tool-budget-exceeded`

The server's tool definitions add up to a large context cost.

## Why it matters

Every tool definition the server advertises is prepended to every prompt the model sees. A
server whose definitions total several thousand tokens has spent that budget before it has
read a word the user said, and it spends it again on the next turn, and the next. That
context is not free: it competes with the conversation history for the same window, and it
is the pile of text the model has to search to pick one tool out of.

This is the server-level view of MCP050. One oversized tool is a local problem; a surface
that is large in aggregate -- lots of tools, each reasonable on its own -- is a budget
problem you only see by adding them up.

## Triggers when

The sum of every tool's definition estimates above about 5000 tokens, using the same
characters-over-four estimate as MCP050. The threshold sits well above a focused,
well-documented server: the careful fixture in this repo totals around 1600 tokens across
eight tools.

## Before

A single server exposing thirty tools, each with a full paragraph of description and a
dozen parameters -- around 8000 tokens of definitions, carried on every request:

```
inventory-server
  add_item, remove_item, update_item, move_item, count_items, ...
  ... 30 tools, ~270 tokens each ...
```

## After

Trim the longest definitions (MCP050 names them), fold near-duplicates into one tool, and
split rarely-used tools onto a second server the client only loads when it needs them:

```
inventory-server        12 core tools   ~2600 tokens
inventory-admin-server   8 admin tools   loaded only for admin sessions
```
