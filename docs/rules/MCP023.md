# MCP023 -- unconstrained well-known format

**Severity:** warning &nbsp;&nbsp; **Rule name:** `unconstrained-well-known-format`

A date, email, or URL parameter declares no format or pattern.

## Why it matters

This is where `2026-01-31`, `31/01/2026`, and `last Tuesday` all arrive at the same
endpoint. Dates, emails, and URLs have well-known syntaxes, and a schema that
declines to name one leaves every model to pick its own convention -- so a call that
worked in testing fails in production against a different model.

A `format` costs one line and removes the entire class of failure. A concrete example
in the description removes what is left.

## Triggers when

A string parameter with no `format`, `pattern`, `enum`, or `const`, whose *name*
implies a well-known syntax: date-like (`date`, `time`, `when`, `since`, `until`, or
a `_at` / `_on` suffix), email-like, or URL-like.

Only the name triggers this, never the description. Triggering on description text
was tried and is a false-positive machine: a search tool whose `query` description
mentions matching on an email address is not itself an email parameter.

## Before

```python
when: str = ""
```

## After

```python
since: Annotated[str | None, Field(
    default=None,
    json_schema_extra={"format": "date"},
    description="Only return comments posted on or after this date, as
                 ISO-8601, e.g. '2026-01-31'.",
)] = None
```
