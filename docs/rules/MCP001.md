# MCP001 -- near-duplicate tool names

**Severity:** error &nbsp;&nbsp; **Rule name:** `near-duplicate-tool-names`

Two tools have names that reduce to the same words.

## Why it matters

A model ranks tools by matching the request against their names before it reads a
single description. When two names reduce to the same words, the name contributes
nothing to that ranking and the choice falls entirely to the descriptions -- which,
on a server that has both `ticket` and `ticket2`, are usually just as similar.

The failure is silent. The model picks one, the call succeeds, and nobody finds out
the wrong ticket system was written to until someone goes looking.

## Triggers when

Two or more tools whose names produce the same token sequence after splitting on
case and separators, dropping pure-digit tokens, and singularising. That covers
`ticket` versus `ticket2`, `getUser` versus `get_user`, and `list_item` versus
`list_items`.

## Before

```python
@mcp.tool()
def ticket(subject: str, body: str) -> Ticket:
    """Creates a ticket in the support system."""

@mcp.tool()
def ticket2(subject: str, body: str) -> Ticket:
    """Creates a ticket."""
```

## After

```python
@mcp.tool()
def create_support_ticket(subject: str, body: str) -> Ticket:
    """Open a customer-facing support ticket. For an internal engineering
    problem, use `create_incident_ticket` instead."""

@mcp.tool()
def create_incident_ticket(subject: str, body: str) -> Ticket:
    """Open an internal engineering incident, visible only to staff. For a
    customer-reported problem, use `create_support_ticket` instead."""
```
