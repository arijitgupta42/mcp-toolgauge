# MCP050 -- oversized tool definition

**Severity:** info &nbsp;&nbsp; **Rule name:** `single-tool-definition-too-large`

A single tool's definition is large enough to crowd out its neighbours.

## Why it matters

The whole list of tool definitions is sent to the model on every request, so a tool with
a sprawling description or a giant schema costs that many tokens *every call* -- whether or
not it is the tool being used. Those tokens come out of the same context window the
conversation needs, and they sit next to every other tool, where the model is trying to
tell them apart.

Good documentation is not the target here. There is a difference between what a model needs
to *choose* a tool -- a crisp sentence about what it does and when to reach for it -- and
what it needs to *use* one, which is per-parameter detail read only after the tool is
already selected. The first belongs in the description; the second belongs in the parameter
descriptions, where it is not weighed against every sibling on every prompt.

## Triggers when

One tool's definition -- its name, description, and input schema together -- estimates above
about 800 tokens, counted crudely as characters over four. The estimate is deliberately
rough: the rule asks whether a definition is big enough to matter, which does not need an
exact token count.

## Before

```python
@mcp.tool()
def create_ticket(subject: str, body: str, priority: str) -> Ticket:
    """Create a support ticket.

    This tool creates a support ticket in the system. A support ticket is a record
    of a customer request. Tickets have a subject, which is a short summary, and a
    body, which is the full text, and a priority, which is how urgent it is. The
    priority can be low, which means... [400 more lines of prose repeating the schema,
    an API changelog, and three worked examples of the response format] ...
    """
```

## After

```python
@mcp.tool()
def create_ticket(
    subject: Annotated[str, "One-line summary, e.g. 'Login page returns 500'"],
    body: Annotated[str, "Full description of the problem, in the user's words"],
    priority: Literal["low", "normal", "high", "urgent"] = "normal",
) -> Ticket:
    """File a new support ticket for a customer request. Use this to open work; to
    change an existing ticket use `update_ticket`."""
```
