# MCP052 -- too many tools

**Severity:** warning &nbsp;&nbsp; **Rule name:** `too-many-tools`

The server has enough tools that selection accuracy suffers.

## Why it matters

Tool selection is a choice between options, and the choice gets harder as the list grows.
Past a few dozen tools, a model spends its attention telling near-identical options apart --
`get_user`, `fetch_user`, `lookup_user`, `find_user_by_id` -- and picks the wrong one more
often. This is the same failure `eval` measures from the other side: the confusion matrix
fills in as the tools that look alike start taking each other's traffic.

More tools is not more capability past this point. A server with sixty narrow tools is
usually a handful of real operations that have been split too finely, and a model routes a
handful of operations far more reliably than sixty variations on them.

## Triggers when

The server advertises more than 40 tools. The number is a rule of thumb, not a cliff:
selection degrades gradually as the count climbs, and 40 is where it is usually clearly
worse than a focused server. It sits well above the fixtures in this repo (8 and 10 tools).

## Before

```
crm-server   58 tools
  get_contact, fetch_contact, lookup_contact_by_email, lookup_contact_by_phone,
  find_contact, search_contacts, list_contacts, get_contact_details, ...
```

## After

Collapse the variations into one tool that takes how you want to look something up, and
split genuinely separate domains onto their own servers:

```
crm-contacts-server   9 tools   (get_contact takes an email, phone, or id)
crm-deals-server      7 tools
crm-reports-server    5 tools
```
