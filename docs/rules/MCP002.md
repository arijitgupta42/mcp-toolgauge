# MCP002 -- non-descriptive tool name

**Severity:** warning &nbsp;&nbsp; **Rule name:** `non-descriptive-tool-name`

Every word in the name is generic, so it says nothing about what the tool does.

## Why it matters

The name is the shortest string a server publishes and the one a model weighs most
heavily, so it carries more meaning per character than anything else you write. A
name built only from filler -- `run`, `get_data`, `doStuff` -- matches every request
weakly and no request strongly.

It costs you at the other end too. When a user asks what just happened, `run` tells
them nothing, and an agent narrating its own actions can only say it called `run`.

## Triggers when

Every word in the name is drawn from a fixed vocabulary of bare verbs (`get`, `run`,
`list`, `do`, `handle`) and empty nouns (`data`, `thing`, `payload`, `handler`).
Digits are ignored. `get_user_profile` does not trigger it: `user` and `profile` are
doing work.

## Before

```python
@mcp.tool()
def get_data(id: str) -> dict:
    """Get data."""
```

## After

```python
@mcp.tool()
def get_user_profile(user_id: str) -> UserProfile:
    """Retrieve the full profile for one person, including contact details."""
```
