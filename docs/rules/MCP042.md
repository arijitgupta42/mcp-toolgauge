# MCP042 -- missing idempotentHint

**Severity:** info &nbsp;&nbsp; **Rule name:** `missing-idempotent-hint`

A tool that changes state declares no idempotentHint.

## Why it matters

`idempotentHint` answers one question: if a call times out, may the client try again?
Without an answer the safe assumption is no, so the user gets asked to sort out a
call that may or may not have happened.

The answer is often yes and costs nothing to declare. Setting a status to `closed` is
idempotent; opening a new ticket is not.

## Triggers when

`idempotentHint` is unset and the tool does not look like a read. Tools that read are
skipped so that a server gets one annotation finding per tool rather than two -- for
those, MCP041 is the finding that changes behaviour.

## Before

```python
@mcp.tool(annotations=ToolAnnotations(readOnlyHint=False))
def update_ticket_status(ticket_id: str, status: TicketStatus) -> Ticket: ...
```

## After

```python
@mcp.tool(annotations=ToolAnnotations(
    readOnlyHint=False, destructiveHint=False, idempotentHint=True
))
def update_ticket_status(ticket_id: str, status: TicketStatus) -> Ticket: ...
```
